# Тестирование реакции водителя АТС
Desktop приложения для определения времени реакции водителя на опредлённый раздражитель, которая представляет собой клиентскую часть (приложение с тестами) и часть адмистратора (приложение для контролем за пользователями и тестовыми сессиями).
Основная ценность разработки - снижение рисков ДТП.

## Ключ шифрования, версия и номер программы

ФИО, пол и другие персональные данные пользователей хранятся в базе в зашифрованном виде (AES). Вручную ничего настраивать не нужно:

- **Название и версия** задаются при сборке. Версия указана один раз в корневом `gradle.properties` (`app.version`), название — в `appName` build-скрипта приложения. Оттуда они попадают и в установщик, и на экран «О программе» (через сгенерированный ресурс `program.properties`). Чтобы выпустить новую версию, достаточно поменять `app.version`.
- **Где лежат данные.** Базы, настройки и ключ: Windows — `C:\Users\<пользователь>\AppData\Local\Reaction test\`, macOS — `~/Library/Application Support/Reaction test/`, Linux — `~/.local/share/Reaction test/`. Таблица Excel со всеми результатами и попытками («База тестирования.xlsx») по умолчанию — в `Документы/Reaction test`, папку можно сменить в настройках; путь к файлу показывается на экране итогов теста, клик по нему открывает файл в Проводнике / Finder.
- **Ключ шифрования** создаётся автоматически при первом запуске, если в базах ещё нет пользователей и сессий. Ключ сохраняется в папке данных (см. выше) (`key-local.bin` для локальных баз, `key-network.bin` для сетевых) и защищён средствами Windows (DPAPI): прочитать его может только та же учётная запись Windows на этом же компьютере.
- **Уникальный номер программы** тоже создаётся при первом запуске и хранится в `%LOCALAPPDATA%\Reaction test\program-number.txt`.

Если ключа нет, а в базе уже есть пользователи, программа новый ключ **не создаёт** (иначе старые данные стали бы нечитаемыми) и при запуске сообщает, что нужен `app\config.json`.

### Файл `app\config.json` — перенос ключа

Файл нужен только тогда, когда несколько компьютеров или учётных записей работают с **одной и той же** базой:

- режим «Сеть» (`ethernet-application-reaction-test` и `ethernet-application-admin`): все компьютеры работают с общей базой на сетевом диске, поэтому ключ у них должен быть одинаковым;
- перенос базы на другой компьютер или в другую учётную запись Windows;
- резервная копия ключа. Без ключа данные восстановить нельзя, а DPAPI-ключ может стать недоступным после переустановки Windows или сброса пароля учётной записи администратором.

Если при запуске рядом с программой лежит `app\config.json`, программа берёт ключ из него, а не из сохранённого, и сохраняет его к себе. После первого запуска файл можно удалить: ключ останется в `%LOCALAPPDATA%`. Файл содержит секретный ключ, поэтому в репозиторий **не коммитится** (`app/config.json` есть в `.gitignore`). Шаблон — [`docs/config.example.json`](docs/config.example.json):

```json
{
  "cryptography": {
    "secret_key": "ЗАМЕНИТЕ_НА_КЛЮЧ_32_СИМВОЛА_HEX",
    "algorithm": "AES",
    "transformation": "AES/ECB/PKCS5Padding"
  },
  "program_data": {
    "number": "ЗАМЕНИТЕ_НА_НОМЕР_ПРОГРАММЫ"
  }
}
```

| Поле | Назначение |
|---|---|
| `cryptography.secret_key` | Ключ шифрования. |
| `cryptography.algorithm` | `AES`. |
| `cryptography.transformation` | `AES/ECB/PKCS5Padding`. Режимы с вектором инициализации (CBC, GCM и т.п.) **не подходят**: код не сохраняет IV, и данные потом не расшифруются. |
| `program_data.number` | Необязательно. Если указан, на экране «О программе» будет этот номер вместо сгенерированного. |

Поля `program_data.name` и `version` из старых версий файла больше не используются, их можно оставить или удалить.

**Как получить файл для сетевого режима.** Перед первым запуском на любом из компьютеров запустите утилиту «Генерация уникального кода» (`./gradlew :desktop-application:generate-code-application:run`). Оставьте «Размер ключа (бит)» = **128** и нажмите генерацию. Затем перенесите значения «Ключ» и «Номер программы» в шаблон. Генерировать можно один раз за запуск утилиты, поэтому скопируйте оба значения сразу. Получившийся `config.json` положите в папку `app` рядом с программой на каждом компьютере.

Почему именно 128 бит: приложение использует байты hex-строки как есть и не декодирует её. Для AES длина `secret_key` должна быть **ровно 16, 24 или 32 символа**. Генератор выдаёт строку длиной `размер / 4`, поэтому подходят только размеры **64, 96 или 128**. При другой длине шифрование упадёт с ошибкой `Invalid AES key length`.

**Если программа уже где-то работает со старым `app\config.json`**, ничего делать не нужно: при запуске новой версии ключ из файла будет подхвачен и сохранён.

**Как получить ключ с компьютера, где его создала программа.** Ключ создаётся автоматически и хранится зашифрованным через DPAPI. Если резервная копия нужна, сделайте `app\config.json` заранее утилитой генерации, до первого запуска программы.

### Куда класть `config.json`

- **Установленное приложение:** `<папка, из которой запускается программа>\app\config.json`.
- **Запуск из Gradle** (`./gradlew :desktop-application:<приложение>:run`): рабочая директория — папка модуля, т.е. `desktop-application\<приложение>\app\config.json`.

## Методика измерения

### Общее для всех тестов

- Перед запуском теста открывается окно в два шага. Шаг 1 — устройство ввода (клавиатура или мышь), «Количество попыток» и «Интервал до сигнала» (у PVT протокол фиксирован, попытки и интервал не выбираются). Шаг 2 — обучение слайдами: что будет на экране, как отвечать выбранным устройством, что считается ошибкой, порядок тренировки.
- **Ответ с клавиатуры** (рекомендуется): пальцы заранее лежат на клавишах, поэтому в результат не входит время перемещения руки. Клавиши: в тестах с педалью — Пробел; в тесте «Светофор» — ← красный, ↓ жёлтый, → зелёный. Автоповтор удерживаемой клавиши не считается ответом. В режиме клавиатуры нажатия мышью не учитываются, и наоборот. При ответе мышью в тесте «Светофор» в результат входит время перевода курсора между кнопками.
- Измеряется время реакции **рукой**; реакция ногой в реальном вождении дольше (плюс перенос ноги с газа на тормоз), пересчитать одно в другое нельзя. Сравнивать результаты корректно только при одинаковом устройстве ввода — оно записывается в сессию («Устройство ввода»).
- Сначала идут 5 тренировочных попыток (`PRACTICE_TRIALS`), чтобы испытуемый привык к тесту; их результаты никуда не записываются. После тренировки испытуемый нажимает «Начать тест», и начинается зачётная часть — только она сохраняется в БД и Excel.
- Перед тренировкой и перед зачётной частью идёт обратный отсчёт 10 с. Перед каждым сигналом — случайный интервал, равномерно распределённый в выбранном диапазоне, чтобы не вырабатывался условный рефлекс на ритм.
- **Начало сигнала** — момент первой отрисовки кадра со стимулом. **Реакция** — момент *нажатия* клавиши или кнопки мыши (не отпускания). Обе отметки берутся из монотонных часов `System.nanoTime()`. Задержку монитора, клавиатуры и мыши программа измерить не может: она входит в результат как постоянная аппаратная составляющая, поэтому сравнивать результаты корректно на одинаковом оборудовании.
- «Количество попыток» — число предъявленных сигналов. Как из попыток получаются итоговые числа — в разделе [«Как считаются итоговые показатели»](#как-считаются-итоговые-показатели).

### Типы ошибок

| Ошибка | Когда засчитывается | Попытка засчитана |
|---|---|---|
| Раннее нажатие (фальстарт до сигнала) | нажатие до сигнала | нет — интервал до сигнала начинается заново |
| Слишком быстрый ответ (упреждение) | нажатие быстрее 100 мс после сигнала | да |
| Неверная реакция | нажата не та клавиша / кнопка, нажатие на запрещающий сигнал | да |
| Пропуск сигнала | нужная реакция не выполнена за отведённое время | да |

В БД и Excel сохраняются общее число ошибок, разбивка по видам и каждая попытка (лист «Попытки»).

### Как считаются итоговые показатели

Все итоговые числа считаются **только по зачётной части** — тренировочные попытки отбрасываются. Исходные данные — список попыток (лист «Попытки», таблица `SessionTrials`); всё остальное вычисляется из него и может быть пересчитано заново.

#### Исход каждой попытки

Время реакции **RT = момент нажатия − момент первой отрисовки сигнала** (для звука — момент фактического начала воспроизведения), мс, по часам `System.nanoTime()`. Каждой попытке присваивается один исход:

| Исход | Условие | Входит в RT-статистику | Это ошибка |
|---|---|---|---|
| Верная реакция | нужный ответ, RT ≥ 100 мс, в пределах окна ответа | да | нет |
| Верное торможение | запрещающий сигнал выдержан без нажатия (только тест 2) | нет | нет |
| Неверная реакция | не тот ответ / нажатие на запрещающий сигнал, RT ≥ 100 мс | нет | да |
| Слишком быстрый ответ | любое нажатие с RT < 100 мс | нет | да |
| Пропуск сигнала | нет нужного нажатия за окно ответа | нет | да |
| Раннее нажатие | нажатие до сигнала; RT записывается отрицательным (на сколько раньше запланированного сигнала) | нет | да |

Раннее нажатие не считается предъявленным сигналом: после него интервал до сигнала начинается заново, а попытка повторяется.

Окна ответа: тесты 2, 3, 5 — 2 с; тест 1 — без ограничения; РДО — 1 с после пересечения линии; PVT — 30 с (тайм-аут).

#### Основные показатели (все тесты, кроме отмеченных особенностей)

Пусть RT₁…RTₙ — времена **верных реакций** (n — «Учтено правильных реакций»), N — число предъявленных сигналов («Предъявлено сигналов» / «Количество попыток»; ранние нажатия в N не входят).

| Показатель | Формула | Если данных мало |
|---|---|---|
| Среднее время реакции | (RT₁ + … + RTₙ) / n | n = 0 → записывается 0, на экране «нет учтённых ответов» |
| Стандартное отклонение (SD) | √(Σ(RTᵢ − среднее)² / (n − 1)) — выборочное | n < 2 → 0 |
| Медиана | центральное значение упорядоченного ряда RT; при чётном n — полусумма двух центральных | n = 0 → не записывается |
| Среднее 10 % самых быстрых | среднее k наименьших RT, k = ⌈0,1 · n⌉ (не меньше 1) | n = 0 → не записывается |
| Среднее 10 % самых медленных | среднее k наибольших RT, k = ⌈0,1 · n⌉ | n = 0 → не записывается |
| Коэффициент вариации | SD / среднее · 100 % | n < 2 → не записывается |
| Доля правильных ответов | (верные реакции + верные торможения) / N · 100 % | N = 0 → не записывается |

В БД и Excel среднее и SD хранятся **в секундах**, остальные показатели времени — в миллисекундах; на экранах всё показывается в миллисекундах. Медиана и 10 % быстрых/медленных реакций устойчивее к единичным выбросам, чем среднее; коэффициент вариации показывает стабильность реакции независимо от её скорости.

#### Ошибки

| Показатель (ключ на листе «Показатели») | Что считается |
|---|---|
| Ошибок всего (`errors_total`) | неверные реакции + пропуски + ранние нажатия + слишком быстрые ответы |
| Неверные реакции (`wrong_responses`) | число исходов «Неверная реакция» |
| Пропуски сигнала (`omissions`) | число исходов «Пропуск сигнала» |
| Ранние нажатия (`false_starts`) | число нажатий до сигнала |
| Слишком быстрые ответы (`anticipations`) | число ответов с RT < 100 мс |

В основных полях сессии (БД, лист «Данные тестирования») «Фальстарты» = ранние нажатия + слишком быстрые ответы.

#### Особенности тестов

- **1. Светофор (выбор).** Верная реакция — клавиша/кнопка цвета горящей лампы. Пропусков нет (окно ответа не ограничено). Показатели — основные.
- **2. Светофор — педаль (go/no-go).** Верная реакция — газ на зелёный; верное торможение — красный или жёлтый выдержан 2 с без нажатия; нажатие на красный/жёлтый — неверная реакция; нет нажатия на зелёный — пропуск. RT-статистика — только по зелёному. Дополнительно (ранние нажатия не учитываются, слишком быстрый ответ на красный/жёлтый считается ложной тревогой):
  - доля попаданий H = попадания / сигналов «зелёный» · 100 %;
  - доля ложных тревог F = нажатия на красный и жёлтый / сигналов «красный» и «жёлтый» · 100 %;
  - для d′ и c доли берутся с поправкой Hautus: H′ = (попадания + 0,5) / (зелёных + 1), F′ = (ложные тревоги + 0,5) / (красных и жёлтых + 1);
  - **d′ = z(H′) − z(F′)** — насколько хорошо человек различает сигналы (0 — не различает);
  - **c = −(z(H′) + z(F′)) / 2** — склонность: c > 0 — осторожность (чаще не нажимает), c < 0 — импульсивность (нажимает на всё);
  - z — обратная функция стандартного нормального распределения. Если за тест не было ни одного зелёного или ни одного красного/жёлтого сигнала, эти четыре показателя не записываются.
- **3. Простая реакция и 5. Звуковой сигнал.** Один вид сигнала; неверных реакций нет. Показатели — основные; у теста 5 дополнительно «Буфер аудиовыхода» (мс).
- **4. РДО.** Вместо RT для каждой попытки записывается **ошибка остановки e = момент нажатия − момент пересечения линии**, мс (− опережение, + запаздывание). Любое нажатие во время движения — верная реакция (порога 100 мс нет), поэтому «Доля правильных ответов» не считается. По ошибкам e₁…eₙ:
  - средняя ошибка со знаком = Σeᵢ / n — систематический сдвиг;
  - средняя абсолютная ошибка = Σ|eᵢ| / n, медиана |e| — точность;
  - SD ошибки — выборочное, по eᵢ со знаком (n < 2 → не записывается);
  - опережения: e < −20 мс; точные остановки: |e| ≤ 20 мс; запаздывания: e > 20 мс;
  - **индекс баланса = (запаздывания − опережения) / (запаздывания + опережения)**, от −1 (только опережения, преобладание возбуждения) до +1 (только запаздывания, преобладание торможения); если все остановки точные — не записывается;
  - средняя абсолютная ошибка отдельно для времени подъезда 1,5 / 2,0 / 2,5 с;
  - в основных полях сессии «среднее» = средняя абсолютная ошибка, «SD» = SD ошибки со знаком (в секундах).
- **6–7. PVT.** Попытки идут до конца времени теста, N — сколько сигналов успело быть предъявлено. RT-статистика — по всем реакциям ≥ 100 мс, **включая медленные (≥ 500 мс)**; тайм-ауты в неё не входят. Дополнительно:
  - провалы внимания = число реакций с RT ≥ 500 мс + тайм-ауты (провалы ≥ 500 мс в «Ошибок всего» не входят — это верные, но медленные реакции);
  - фальстарты = ранние нажатия + слишком быстрые ответы;
  - **показатель выполнения = (1 − (провалы + фальстарты) / (N + фальстарты)) · 100 %**;
  - средняя скорость реакции = среднее значений 1000 / RTᵢ, 1/с (чувствительнее к недосыпу, чем среднее RT);
  - средняя скорость 10 % самых медленных реакций — среднее k наименьших значений 1000 / RT, k = ⌈0,1 · n⌉.

#### Служебные показатели

- **Тренировочных попыток перед тестом** (`practice_trials`) — 5 или 0, если тренировку пропустили. Сессии без тренировки обычно медленнее и с большим числом ошибок; при анализе их лучше рассматривать отдельно.
- **Номер сессии пользователя** — какой раз человек проходит этот тест (эффект научения: результаты первых сессий обычно хуже).
- **Устройство ввода, версия методики, рабочее место** — см. «Что записывается». Сравнивать между собой корректно сессии с одинаковыми устройством ввода, версией методики и (для абсолютных значений) оборудованием.

### Что записывается

Все перечисленные ниже данные сохраняются **и в БД сессий** (таблицы `Sessions` и `SessionTrials`; персональные данные и сведения о самочувствии — в зашифрованном виде), **и в Excel**. На экране «О пользователе» в карточке сессии показываются все данные, медиана и график времени реакции по попыткам; общий график строится по тому же фильтру номера теста, что и список сессий.

#### Excel

**Лист «Данные тестирования»** — одна строка на сессию: результаты, данные водителя, а также

- **ведущая рука** — указывается при регистрации пользователя;
- **номер сессии пользователя** — какой по счёту раз человек проходит этот тест (для учёта натренированности);
- **состояние перед тестом** — анкета на экране входа: очки/линзы, часов сна за сутки, самочувствие 1–5, рука для ответа; **устройство ввода** (клавиатура или мышь) — из окна перед запуском теста. Это сведения о здоровье — получение согласия испытуемого на их обработку остаётся за организацией, проводящей тестирование;
- **рабочее место** — монитор (модель и размер изображения из EDID, только Windows; при нескольких мониторах записываются все), диагональ, разрешение, частота обновления, масштаб ОС, размер окна теста, имя компьютера, ОС, версия программы и **версия методики** (сейчас 3: обучение, тренировка и ответ с клавиатуры; данные версий 1 и 2 получены по прежней методике и с новыми напрямую несопоставимы).

**Лист «Показатели»** — показатели, специфичные для теста (медиана, d′, провалы PVT, ошибки РДО и т. д., см. описание тестов ниже): одна строка на показатель, со стабильным ключом для анализа.

**Лист «Попытки»** — одна строка на каждый сигнал и каждый фальстарт: номер попытки, сигнал, интервал до сигнала, исход, время реакции (для фальстарта до сигнала — отрицательное: на сколько раньше сигнала было нажатие). По нему можно считать медиану, динамику утомления, влияние интервала до сигнала.

### Тесты

Все тесты — в дорожной сцене (вид сверху). Испытуемый отвечает клавишей (рекомендуется) или левой кнопкой мыши по педали или кнопке на экране.

#### Порядок прохождения

1. **Параметры.** В меню тестов при выборе теста открывается окно: устройство ввода (клавиатура или мышь), количество попыток и интервал до сигнала. У PVT попытки и интервал не выбираются, протокол фиксирован.
2. **Обучение** — слайды с картинками, листаются кнопками «Назад»/«Далее»: что будет на экране; как отвечать выбранным устройством (нарисованные клавиши или мышь с выделенной левой кнопкой); что считается ошибкой; порядок тренировки и теста.
3. **Тренировка** — 5 попыток с подписью «Тренировка: попытка N из 5»; результаты не сохраняются. На последнем слайде обучения тренировку можно пропустить («Пропустить тренировку») — например, если человек уже проходил тест; в результаты пишется показатель «Тренировочных попыток перед тестом» (5 или 0). Для PVT тренировка — 5 сигналов, дальше тест идёт по времени.
4. **Зачётная часть** — после кнопки «Начать тест» на экране «Тренировка окончена». Перед тренировкой и перед зачётной частью идёт обратный отсчёт 10 с. В БД и Excel записывается только зачётная часть.

#### Ответ

| Тест | Клавиатура | Мышь (левая кнопка) |
|---|---|---|
| 1. Светофор | ← красный, ↓ жёлтый, → зелёный | цветная кнопка под светофором |
| 2. Светофор — педаль | Пробел — газ | педаль газа |
| 3–7 | Пробел — тормоз | педаль тормоза |

- **Клавиатура** рекомендуется: пальцы лежат на клавишах весь тест, рука не перемещается, и время движения в результат не входит. При ответе с клавиатуры на кнопках теста «Светофор» подписаны клавиши, а подсказка над сценой называет клавишу («нажмите «Пробел»»).
- **Мышь:** в тесте «Светофор» курсор приходится переводить между тремя кнопками, поэтому в результат входит время движения руки (зависит от расстояния до кнопки, закон Фиттса) — обучение предупреждает об этом и советует клавиатуру. В остальных тестах курсор заранее наводится на педаль.
- Засчитывается только выбранное устройство: в режиме клавиатуры нажатия мышью игнорируются, и наоборот. Автоповтор удерживаемой клавиши не считается ответом.
- Тесты измеряют реакцию **рукой**. В реальном вождении водитель тормозит ногой: это дольше (обычно на 30–100 мс) и включает перенос ноги с газа на тормоз (≈ 0,2 с). Пересчитать результат в реальное время торможения нельзя; сравнивать можно людей между собой и одного человека в динамике при **одинаковом устройстве ввода** (оно записывается в сессию).

| ID | Тест | Что измеряет |
|---|---|---|
| 1 | Светофор — реакция выбора | сложная зрительно-моторная реакция выбора из трёх |
| 2 | Светофор — реакция различения | реакция различения (go/no-go), импульсивность |
| 3 | Остановка на красный свет | простая зрительная реакция |
| 4 | РДО: остановка на стоп-линии | точность реакции на движущийся объект, баланс возбуждения и торможения |
| 5 | Звуковой сигнал | простая слуховая реакция |
| 6 | Бдительность (PVT), 10 мин | устойчивость внимания, утомление, недосып (эталонная длительность) |
| 7 | Бдительность (PVT), 5 мин | то же, укороченная версия |

#### 1. Светофор — реакция выбора
Загорается случайная лампа светофора, нужно ответить её цветом: клавишей ← / ↓ / → или кнопкой того же цвета. Ограничения времени ответа нет. Показатели: среднее, SD, медиана, средние 10 % самых быстрых и самых медленных реакций, коэффициент вариации, доля правильных ответов (формулы — в разделе «Как считаются итоговые показатели»).

#### 2. Светофор — реакция различения (go/no-go)
Загорается случайная лампа, газ (Пробел или педаль газа мышью) нужно нажать только на зелёный (окно ответа 2 с). Отсутствие нажатия на красный/жёлтый — правильный ответ, отсутствие нажатия на зелёный — пропуск. Помимо общих показателей считаются показатели теории обнаружения сигнала: доля попаданий H, доля ложных тревог F, **чувствительность d′ = z(H) − z(F)** и **критерий c = −(z(H) + z(F)) / 2** (c > 0 — осторожность, c < 0 — склонность реагировать на всё). Для устойчивости при 0 % и 100 % применяется поправка log-linear (Hautus, 1995): H = (попадания + 0,5) / (сигналы + 1), F аналогично.

#### 3. Остановка на красный свет
Машина едет, светофор впереди горит зелёным. В случайный момент загорается красный — нужно нажать тормоз (Пробел или педаль тормоза мышью; окно ответа 2 с). Время реакции отсчитывается от первой отрисовки красного. Торможение на зелёный — фальстарт, отсутствие торможения — пропуск (проезд на красный).

#### 4. РДО: остановка на стоп-линии
Дорожный вариант классической методики «реакция на движущийся объект». Машина стоит у правого края, после случайной паузы с постоянной скоростью едет к стоп-линии у красного светофора. Нужно нажать тормоз **точно в момент**, когда передний бампер окажется на линии; машина останавливается там, где нажат тормоз.

- Время движения до линии на каждой попытке случайно выбирается из 1,5 / 2,0 / 2,5 с — три скорости, чтобы нельзя было заучить ритм.
- **Ошибка = момент нажатия − момент пересечения линии**, мс: отрицательная — опережение (преобладание возбуждения), положительная — запаздывание (преобладание торможения). Положение машины на экране и ошибка рассчитываются от одних и тех же часов.
- Показатели: средняя ошибка со знаком, средняя и медианная абсолютная ошибка, SD ошибки, число опережений / точных остановок (±20 мс ≈ один кадр при 50–60 Гц) / запаздываний, **индекс баланса (з − о) / (з + о)** от −1 до +1, средняя абсолютная ошибка отдельно для каждой скорости.
- В общих полях БД «среднее» — средняя абсолютная ошибка, «SD» — SD ошибки со знаком.
- Нажатие, пока машина стоит, — фальстарт; нет нажатия за 1 с после пересечения линии — пропуск.
- Порог «точной» остановки ±20 мс — соглашение; по листу «Попытки» можно пересчитать с любым порогом.

#### 5. Звуковой сигнал
Машина едет по дороге; в случайный момент звучит клаксон (два тона 420 и 500 Гц, 400 мс, фронт 2 мс) — нужно нажать педаль тормоза (окно ответа 2 с).

- Начало сигнала — момент, когда аудиосистема **фактически начала воспроизводить** звук: линия вывода открыта заранее и непрерывно получает тишину, а отдельный поток отслеживает позицию воспроизведения и фиксирует момент, когда она доходит до первого отсчёта клаксона. Так исключается задержка открытия устройства и очереди программы.
- Задержку звуковой карты, драйвера и наушников программа измерить не может (обычно 5–40 мс на Windows); размер буфера записывается в показатель «Буфер аудиовыхода». Для сравнимости проводить тест **на одном и том же оборудовании в наушниках при фиксированной громкости**.
- Если звуковое устройство недоступно, тест не запускается.

#### 6–7. Бдительность (PVT)
Дорожный вариант психомоторного теста бдительности (Psychomotor Vigilance Task; Dinges & Powell, 1985; Basner & Dinges, 2011). Испытуемый долго едет за впереди идущей машиной; в случайный момент у неё загораются стоп-сигналы — нужно нажать тормоз. От лабораторного PVT отличается только видом стимула (стоп-сигналы вместо счётчика миллисекунд); временные параметры стандартные:

- длительность 10 мин (эталон) или 5 мин; тест завершается по времени, номер попытки и оставшееся время не показываются;
- интервал от ответа до следующего сигнала — равномерно 2–10 с (интервал в окне перед тестом не выбирается);
- стоп-сигналы горят до ответа; после ответа 1 с показывается время реакции (как в стандартном PVT);
- нажатие без сигнала или быстрее 100 мс — фальстарт, интервал начинается заново;
- реакция ≥ 500 мс — **провал внимания (lapse)**; нет реакции 30 с — тайм-аут, тоже провал.

Показатели (Basner & Dinges, 2011): число провалов, число фальстартов, **показатель выполнения = 1 − (провалы + фальстарты) / (сигналы + фальстарты)**, медиана RT, **средняя скорость реакции 1/RT** (наиболее чувствительна к недосыпу), среднее 10 % самых быстрых RT, средняя скорость 10 % самых медленных реакций. Среднее и SD в общих полях — по всем реакциям ≥ 100 мс, включая провалы.

### Ограничения достоверности

- **Аппаратная задержка.** Задержку монитора (обычно 10–50 мс), клавиатуры и мыши (обычно 1–30 мс; у клавиатур разброс больше, чем у мышей) и звукового тракта программа измерить не может. Она почти постоянна для одного рабочего места и смещает все результаты на одну величину, поэтому **сравнивать можно результаты, полученные на одинаковом оборудовании**. Для абсолютной калибровки нужен внешний датчик (фотодиод или микрофон).
- **Временное разрешение.** Изображение обновляется с частотой монитора (16,7 мс при 60 Гц), поэтому момент появления зрительного стимула определяется с точностью до кадра. Частота обновления записывается в данные сессии.
- **Нормы.** Тесты 4–7 — адаптации стандартных методик к дорожной сцене. Пороги (100 мс, 500 мс, ±20 мс) взяты из литературы или приняты по соглашению. Нормативные значения для этих вариантов нужно получать на своей выборке; сопоставлять их с лабораторными нормами можно только после пилотной проверки.
- **Условия проведения.** Для сопоставимости проводить тестирование в одинаковых условиях: тихое помещение, ровное освещение, расстояние до экрана около 60 см, одна и та же рука (фиксируется в анкете) и одно устройство ввода (выбирается перед тестом и записывается в сессию).
