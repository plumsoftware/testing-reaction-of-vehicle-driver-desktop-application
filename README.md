# Тестирование реакции водителя АТС
Desktop приложения для определения времени реакции водителя на опредлённый раздражитель, которая представляет собой клиентскую часть (приложение с тестами) и часть адмистратора (приложение для контролем за пользователями и тестовыми сессиями).
Основная ценность разработки - снижение рисков ДТП.

## Файл конфигурации `app\config.json`

Приложения, работающие с пользователями (гибрид, клиент с тестами, администратор), при запуске читают файл `app\config.json` относительно рабочей директории процесса — то есть из папки `app` рядом с местом запуска программы. Без него приложение падает с ошибкой «Файл конфигурации для ключей не найден». Генератору кода этот файл не нужен.

Файл содержит секретный ключ, поэтому в репозиторий **не коммитится** (`app/config.json` добавлен в `.gitignore`). Шаблон лежит в [`docs/config.example.json`](docs/config.example.json):

```json
{
  "cryptography": {
    "secret_key": "ЗАМЕНИТЕ_НА_КЛЮЧ_32_СИМВОЛА_HEX",
    "algorithm": "AES",
    "transformation": "AES/ECB/PKCS5Padding"
  },
  "program_data": {
    "name": "Тест на реакцию",
    "version": "1.0.0",
    "number": "ЗАМЕНИТЕ_НА_НОМЕР_ПРОГРАММЫ"
  }
}
```

### Поля

| Поле | Назначение |
|---|---|
| `cryptography.secret_key` | Ключ шифрования ФИО и пола пользователей в базе данных. |
| `cryptography.algorithm` | Алгоритм для `javax.crypto.spec.SecretKeySpec` (например, `AES`). |
| `cryptography.transformation` | Строка для `javax.crypto.Cipher.getInstance` (например, `AES/ECB/PKCS5Padding`). |
| `program_data.name` / `version` / `number` | Название, версия и уникальный номер программы — выводятся на экране «О программе». |

### Откуда брать значения

**Если программа уже где-то развёрнута и в базах есть пользователи** — не генерируйте ничего заново: скопируйте `app\config.json` целиком с компьютера, где программа уже работает (или от администратора/разработчика, который её устанавливал). Ключ и параметры шифрования невозможно восстановить из кода или из базы.

**Если это первая установка (базы пустые)** — заполните файл так:

| Поле | Откуда взять |
|---|---|
| `secret_key` | Запустите «Генерация уникального кода» (`./gradlew :desktop-application:generate-code-application:run`), оставьте «Размер ключа (бит)» = **128** и нажмите генерацию. Скопируйте значение из поля «Ключ» (32 символа). |
| `number` | Из того же окна генератора — поле «Номер программы» (64 символа). Генерировать можно только один раз за запуск, поэтому скопируйте оба значения сразу. |
| `algorithm` | Впишите `AES`. Генератор это поле не заполняет. |
| `transformation` | Впишите `AES/ECB/PKCS5Padding`. Режимы с вектором инициализации (CBC, GCM и т.п.) **не подходят**: код не сохраняет IV, и данные потом не расшифруются. |
| `name` | Произвольное название, которое будет показано на экране «О программе». Удобно взять `packageName` приложения из его `build.gradle.kts` (например, `Тест на реакцию`). |
| `version` | Версия для экрана «О программе» — `packageVersion` из `build.gradle.kts` приложения (сейчас `1.0.0`). |

Почему именно 128 бит: ключ используется как строка — приложение берёт байты hex-строки как есть, а не декодирует её. Для AES длина строки `secret_key` должна быть **ровно 16, 24 или 32 символа**. Генератор выдаёт строку длиной `размер / 4`, поэтому допустимы только размеры **64, 96 или 128**. При другой длине шифрование упадёт с ошибкой `Invalid AES key length`.

После этого один и тот же файл разложите на все компьютеры, где установлены приложения.

### Совместимость с существующими данными

Все приложения, работающие с одной базой (в том числе по сети), должны использовать **одинаковые** `secret_key`, `algorithm` и `transformation`. Если базы уже заполнены, используйте тот же ключ, которым они были зашифрованы: с другим ключом ранее сохранённые ФИО пользователей не расшифруются.

### Куда класть файл

- **Установленное приложение:** `<папка, из которой запускается программа>\app\config.json`.
- **Запуск из Gradle** (`./gradlew :desktop-application:<приложение>:run`): рабочая директория — папка модуля, т.е. `desktop-application\<приложение>\app\config.json`.
- Путь в коде записан с обратным слешем (`app\config.json`), поэтому корректно работает только на Windows.

## Методика измерения

### Общее для всех тестов

- Перед первым сигналом идёт обратный отсчёт 10 с. Перед каждым сигналом — случайный интервал, равномерно распределённый в выбранном диапазоне («Интервал сигнала»).
- **Начало сигнала** — момент первой отрисовки кадра со стимулом. **Реакция** — момент *нажатия* кнопки мыши (не отпускания). Обе отметки берутся из монотонных часов `System.nanoTime()`. Задержку монитора и мыши программа измерить не может: она входит в результат как постоянная аппаратная составляющая, поэтому сравнивать результаты корректно на одинаковом оборудовании.
- «Количество попыток» — число предъявленных сигналов.
- В среднее и стандартное отклонение входят **только правильные реакции**. Стандартное отклонение — выборочное (n − 1); при n < 2 записывается 0. Если правильных реакций нет, среднее записывается как 0, а в Excel столбец «Учтено правильных реакций (n)» равен 0.
- В БД и Excel среднее и стандартное отклонение хранятся **в секундах**, на экранах показываются в миллисекундах.

### Типы ошибок

| Ошибка | Когда засчитывается | Попытка засчитана |
|---|---|---|
| Фальстарт | нажатие до сигнала | нет — интервал до сигнала начинается заново |
| Фальстарт (упреждение) | нажатие быстрее 100 мс после сигнала | да |
| Неверная реакция | нажата не та кнопка / нажатие на запрещающий сигнал | да |
| Пропуск сигнала | нужная реакция не выполнена за отведённое время | да |

В БД сохраняется общее число ошибок, в Excel — также разбивка по типам и время каждой правильной реакции.

### Что записывается

Все перечисленные ниже данные сохраняются **и в БД сессий** (таблицы `Sessions` и `SessionTrials`; персональные данные и сведения о самочувствии — в зашифрованном виде), **и в Excel**. На экране «О пользователе» в карточке сессии показываются все данные, медиана и график времени реакции по попыткам; общий график строится по тому же фильтру номера теста, что и список сессий.

#### Excel

**Лист «Данные тестирования»** — одна строка на сессию: результаты, данные водителя, а также

- **ведущая рука** — указывается при регистрации пользователя;
- **номер сессии пользователя** — какой по счёту раз человек проходит этот тест (для учёта натренированности);
- **состояние перед тестом** — анкета на экране входа: очки/линзы, часов сна за сутки, самочувствие 1–5, рука для ответа, устройство ввода. Это сведения о здоровье — получение согласия испытуемого на их обработку остаётся за организацией, проводящей тестирование;
- **рабочее место** — монитор (модель и размер изображения из EDID, только Windows; при нескольких мониторах записываются все), диагональ, разрешение, частота обновления, масштаб ОС, размер окна теста, имя компьютера, ОС, версия программы и **версия методики** (сейчас 2; данные версии 1 получены по прежней методике и с новыми напрямую несопоставимы).

**Лист «Показатели»** — показатели, специфичные для теста (медиана, d′, провалы PVT, ошибки РДО и т. д., см. описание тестов ниже): одна строка на показатель, со стабильным ключом для анализа.

**Лист «Попытки»** — одна строка на каждый сигнал и каждый фальстарт: номер попытки, сигнал, интервал до сигнала, исход, время реакции (для фальстарта до сигнала — отрицательное: на сколько раньше сигнала было нажатие). По нему можно считать медиану, динамику утомления, влияние интервала до сигнала.

### Тесты

Все тесты — в дорожной сцене (вид сверху), ответ — педалью или кнопкой мышью. Количество попыток и интервал до сигнала выбираются на экране входа (кроме PVT, у которого протокол фиксирован).

| ID | Тест | Что измеряет |
|---|---|---|
| 1 | Светофор — реакция выбора | сложная зрительно-моторная реакция выбора из трёх |
| 2 | Светофор — реакция различения | реакция различения (go/no-go), импульсивность |
| 3 | Остановка на красный свет | простая зрительная реакция |
| 4 | РДО: остановка на стоп-линии | точность реакции на движущийся объект, баланс возбуждения и торможения |
| 5 | Звуковой сигнал | простая слуховая реакция |
| 6 | Бдительность (PVT), 10 мин | устойчивость внимания, утомление, недосып (эталонная длительность) |
| 7 | Бдительность (PVT), 5 мин | то же, укороченная версия |

#### 1. Светофор — реакция выбора
Загорается случайная лампа светофора, нужно нажать кнопку того же цвета. Ограничения времени ответа нет. Показатели: среднее, SD, медиана, средние 10 % самых быстрых и самых медленных реакций, коэффициент вариации (SD / среднее), доля правильных ответов.

#### 2. Светофор — реакция различения (go/no-go)
Загорается случайная лампа, педаль газа нужно нажать только на зелёный (окно ответа 2 с). Отсутствие нажатия на красный/жёлтый — правильный ответ, отсутствие нажатия на зелёный — пропуск. Помимо общих показателей считаются показатели теории обнаружения сигнала: доля попаданий H, доля ложных тревог F, **чувствительность d′ = z(H) − z(F)** и **критерий c = −(z(H) + z(F)) / 2** (c > 0 — осторожность, c < 0 — склонность реагировать на всё). Для устойчивости при 0 % и 100 % применяется поправка log-linear (Hautus, 1995): H = (попадания + 0,5) / (сигналы + 1), F аналогично.

#### 3. Остановка на красный свет
Машина едет, светофор впереди горит зелёным. В случайный момент загорается красный — нужно нажать педаль тормоза (окно ответа 2 с). Время реакции отсчитывается от первой отрисовки красного. Торможение на зелёный — фальстарт, отсутствие торможения — пропуск (проезд на красный).

#### 4. РДО: остановка на стоп-линии
Дорожный вариант классической методики «реакция на движущийся объект». Машина стоит у правого края, после случайной паузы с постоянной скоростью едет к стоп-линии у красного светофора. Нужно нажать тормоз **точно в момент**, когда передний бампер окажется на линии; машина останавливается там, где нажат тормоз.

- Время движения до линии на каждой попытке случайно выбирается из 1,5 / 2,0 / 2,5 с — три скорости, чтобы нельзя было заучить ритм.
- **Ошибка = момент нажатия − момент пересечения линии**, мс: отрицательная — опережение (преобладание возбуждения), положительная — запаздывание (преобладание торможения). Положение машины на экране и ошибка рассчитываются от одних и тех же часов.
- Показатели: средняя ошибка со знаком, средняя и медианная абсолютная ошибка, SD ошибки, число опережений / точных остановок (±20 мс ≈ один кадр при 50–60 Гц) / запаздываний, **индекс баланса (з − о) / (з + о)** от −1 до +1, средняя абсолютная ошибка отдельно для каждой скорости.
- В общих полях БД «среднее» — средняя абсолютная ошибка, «SD» — SD ошибки со знаком.
- Нажатие, пока машина стоит, — фальстарт; нет нажатия за 1 с после пересечения линии — пропуск.
- Порог «точной» остановки ±20 мс — соглашение; по листу «Попытки» можно пересчитать с любым порогом.

#### 5. Звуковой сигнал
Машина едет по дороге; в случайный момент звучит клаксон (два тона 420 и 500 Гц, 400 мс, фронт 2 мс) — нужно нажать педаль тормоза (окно ответа 2 с).

- Начало сигнала — момент, когда аудиосистема **фактически начала воспроизводить** звук: линия вывода открыта заранее и непрерывно получает тишину, а отдельный поток отслеживает позицию воспроизведения и фиксирует момент, когда она доходит до первого отсчёта клаксона. Так исключается задержка открытия устройства и очереди программы.
- Задержку звуковой карты, драйвера и наушников программа измерить не может (обычно 5–40 мс на Windows); размер буфера записывается в показатель «Буфер аудиовыхода». Для сравнимости проводить тест **на одном и том же оборудовании в наушниках при фиксированной громкости**.
- Если звуковое устройство недоступно, тест не запускается.

#### 6–7. Бдительность (PVT)
Дорожный вариант психомоторного теста бдительности (Psychomotor Vigilance Task; Dinges & Powell, 1985; Basner & Dinges, 2011). Испытуемый долго едет за впереди идущей машиной; в случайный момент у неё загораются стоп-сигналы — нужно нажать тормоз. От лабораторного PVT отличается только видом стимула (стоп-сигналы вместо счётчика миллисекунд); временные параметры стандартные:

- длительность 10 мин (эталон) или 5 мин; тест завершается по времени, номер попытки и оставшееся время не показываются;
- интервал от ответа до следующего сигнала — равномерно 2–10 с (настройка интервала с экрана входа не используется);
- стоп-сигналы горят до ответа; после ответа 1 с показывается время реакции (как в стандартном PVT);
- нажатие без сигнала или быстрее 100 мс — фальстарт, интервал начинается заново;
- реакция ≥ 500 мс — **провал внимания (lapse)**; нет реакции 30 с — тайм-аут, тоже провал.

Показатели (Basner & Dinges, 2011): число провалов, число фальстартов, **показатель выполнения = 1 − (провалы + фальстарты) / (сигналы + фальстарты)**, медиана RT, **средняя скорость реакции 1/RT** (наиболее чувствительна к недосыпу), среднее 10 % самых быстрых RT, средняя скорость 10 % самых медленных реакций. Среднее и SD в общих полях — по всем реакциям ≥ 100 мс, включая провалы.

### Ограничения достоверности

- **Аппаратная задержка.** Задержку монитора (обычно 10–50 мс), мыши (1–10 мс) и звукового тракта программа измерить не может. Она почти постоянна для одного рабочего места и смещает все результаты на одну величину, поэтому **сравнивать можно результаты, полученные на одинаковом оборудовании**. Для абсолютной калибровки нужен внешний датчик (фотодиод или микрофон).
- **Временное разрешение.** Изображение обновляется с частотой монитора (16,7 мс при 60 Гц), поэтому момент появления зрительного стимула определяется с точностью до кадра. Частота обновления записывается в данные сессии.
- **Нормы.** Тесты 4–7 — адаптации стандартных методик к дорожной сцене. Пороги (100 мс, 500 мс, ±20 мс) взяты из литературы или приняты по соглашению. Нормативные значения для этих вариантов нужно получать на своей выборке; сопоставлять их с лабораторными нормами можно только после пилотной проверки.
- **Условия проведения.** Для сопоставимости проводить тестирование в одинаковых условиях: тихое помещение, ровное освещение, расстояние до экрана около 60 см, одна и та же рука и одно устройство ввода (фиксируются в анкете).
